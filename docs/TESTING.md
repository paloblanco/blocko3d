# BLOCKO3D test history

What was checked by hand (with Playwright and headless Chromium) as features were added, moved here unchanged from `docs/ENGINE.md` on 2026-11-11. The automated checks are `npm test` (see **Testing** in `docs/ENGINE.md`); this file is the record of the deeper, one-off checks behind each feature, useful when changing that feature again. Add to it when you check something new by hand.

There's no test suite in the repo yet. It was verified with Playwright and headless Chromium: launch with `--use-gl=swiftshader --enable-unsafe-swiftshader`, which supports WebGL2.

The tests serve the repo with `python -m http.server`. Nothing is loaded from other sites any more (the IDE uses `vendor/`, games the committed bundle), so no request routing is needed.

What was checked:

- The demo plays: lowering the bridge and walking into the castle works.
- Map painting, tile painting, and autosave persistence after a reload.
- Error → line number → click jumps to the line.
- An API check cart covering:
  - `mget` and `mgetw`, unrotated and rotated.
  - Sphere push-out for pitched, yawed and rolled maps.
  - `map_set_origin` keeping the map in place.
  - `msetw`, `pal` on primitives, and the math helpers.
- The demos, played by autopilots in the exported pages (headless Chromium): Block Pop (160 random clicks pop 128 blocks with no block left floating; a rigged board with one pair ends the game, saves the best score, and a click starts a new game); Tilt Maze (an autopilot following a breadth-first path solves the maze in about 9 s with no tunneling and saves the time; pushing right moves the marble toward -x); Scrambler (runs at full speed; watch, ride and stopped views); First Person (an autopilot opens both iron gates, fetches the key from the far end of the maze, opens the gold gate and escapes, saving the time; mouse-look turns right on a rightward move once captured; on a phone the touch d-pad and O open the first gate, the gold gate stays shut without the key, and a finger drag turns the view). Builder (placing and right-click digging, the build saved and back after a reload, holding X clears it); Bumper Arena (a second simulated pad joins and steers, rounds always finish because the arena crumbles to nothing); Third Person (an autopilot rides the slider, the turning bridge and the elevator, staying on each, collects all five stars and saves the time; it occasionally misses a jump between the stepping stones under SwiftShader's slow frames). All eight load from the IDE's Demos menu, run without errors and open their maps in the editor.
- Standalone demos: with a temporary second demo in the list, the build made `castle/` and `tiny-test/` plus the list page; at phone and desktop size the page lists both and each link runs its game; opened from disk with the network blocked, the list page's link runs the castle with zero requests.

- `mtow`/`wtom`: on a map turned in pitch, yaw and roll with a moved pivot, the origin maps to the map's position, 300 random points round-trip exactly (error about 4e-15) and `wtom` floored matches `mgetw`'s cell for all 300; an unturned map is a pure shift; a quarter-turn yaw takes local +z to world +x. Tilt Maze (autopilot still wins) and Scrambler (watch and ride views) render the same after switching their hand-written rotation math to `mtow`.
- Rays: `mray` on an unrotated map (straight down onto a block and the floor, from the side, up and out of range for a miss, starting inside a block, an unnormalized direction); 400 random rays through a pitched, yawed and rolled map with a moved pivot against brute-force stepping with `mgetw` (all 209 hits on the same block and face, distance within 0.001); clicking on three projected points of a rendered map gives the expected blocks and faces; `mouse_ray` in mode 2 points straight down the view, and a corner ray matches the field of view.
